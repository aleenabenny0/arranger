# Arranger web app

React 19, TypeScript and Vite, typed against the API's own OpenAPI document.
`npm run build` writes static files to `dist/`; FastAPI serves that directory
at `/` (`FRONTEND_DIR`), so the app and the API are one origin and the session
cookie stays first-party. It can also be hosted elsewhere: set the
`<meta name="arranger-api">` content in `index.html` to the API origin and list
the site's origin in the API's `FRONTEND_ORIGINS`.

```bash
npm ci                 # once
npm run api-types      # regenerate src/api/schema.ts from openapi.json (see below)
npm run dev            # http://localhost:5173, API calls proxied to http://127.0.0.1:8000
npm run typecheck      # tsc --noEmit
npm test               # Vitest + Testing Library under jsdom
npx vitest run --coverage
npm run build          # tsc, then vite build -> dist/
```

`openapi.json` is the API's document, exported with
`python -c "import json; from arranger_api.main import app; print(json.dumps(app.openapi()))"`
from the repository root. Regenerate it and the types whenever a route changes;
a path, parameter or body field that no longer exists is then a compile error
in whatever view used it.

## Layout

| Path | What it is |
|---|---|
| `index.html`, `public/styles.css` | The shell and the design system (tokens, light and dark, print). |
| `public/*.html`, `public/js/legal.js` | Draft legal and help pages, filled from `/legal/config`. See `docs/legal-review.md`. |
| `public/vendor/` | Verovio, fetched by `python fetch_vendor.py` and verified by SHA-256. Not committed; copied into `dist/` by the build. |
| `src/api/schema.ts` | Generated by `openapi-typescript`. Do not edit. |
| `src/api/client.ts` | The only module that talks to the server: `openapi-fetch` with a middleware that adds the CSRF header and turns every failure into an `ApiError` with a message fit to show; raw helpers for uploads, MusicXML text, downloads and job polling. |
| `src/api/types.ts` | Shapes of the responses the API leaves as free-form objects. |
| `src/lib/verify.ts` | The browser-side playability check: range, span, polyphony and leap feasibility with a greedy hand assignment, plus `validatePlan`. A preview only; the server's `arranger.verify` is the oracle. |
| `src/lib/player.ts`, `src/lib/notation.ts` | WebAudio playback of the server's note events; Verovio loading, SVG sanitising and finding marks. Plain TypeScript, no React. |
| `src/lib/route.ts`, `focus.ts`, `session.tsx`, `toast.tsx` | Hash routing, heading focus on navigation, who is signed in, status messages and live regions. |
| `src/components/` | `Tabs` (WAI-ARIA pattern), `Dialog` and `ConfirmDialog` (native `<dialog>`, focus returned to the opener), `Field`, `Notation`, `PlayerControls`, `Timeline`. |
| `src/views/` | `Home`, `Auth`, `Password` (forgot, reset, verify), `Library`, `Account`, and `project/` (source and corrections, hands and calibration, arrange with a cancellable job, the result, revisions and comparison, the advanced plan editor). |
| `src/test/` | The Vitest setup, a `fetch` stand-in with recorded calls, and a renderer that supplies a resolved session. |

## Rules this code keeps

- **No `innerHTML`, no `dangerouslySetInnerHTML`, no inline script, no inline
  style, no `eval`.** The content security policy forbids them and CI greps for
  them. Text from the server or the user is always rendered as text. Notation
  SVG is parsed and adopted node by node after scripts, `foreignObject`,
  `style` attributes, event handlers and external references are removed; the
  `<style>` elements Verovio emits are cut out of the text first and applied
  through a constructed `CSSStyleSheet`, which the policy does not govern.
- **Nothing is faked.** Every number on screen comes from the API, except the
  browser check in the Advanced view, which says on screen that it is a
  browser check and not the server's verdict.
- **Results are tied to what they were made from.** An arrangement made from an
  older source revision or a different hand profile is marked out of date.
- **Accessible by construction.** Headings in order, labelled controls, errors
  in words next to the field and announced, focus moved to the new heading on
  navigation, a skip link, WAI-ARIA tabs, native `<dialog>`, findings listed as
  a table as well as marked in the score and on the bar timeline, state never
  shown by colour alone, `prefers-reduced-motion` and `prefers-color-scheme`
  respected, usable at 320 pixels wide.

## Testing

Three suites cover the app, from the inside out:

1. **Vitest** (`src/**/*.test.ts(x)`): every component, every view and the API
   client's error paths, against a `fetch` stand-in. Runs in seconds.
2. **Playwright** (`../e2e/`): the role-based regression suite in Node against
   the real API and the built app.
3. **The Python browser suite** (`../tests/test_browser_e2e.py`): the deeper
   journey with email verification, playback, PDF, axe-core on every view and
   keyboard-only use at phone width.

Both browser suites need `dist/` (`npm run build`) and the notation engine
(`python fetch_vendor.py`, before the build so it is copied into `dist/`).

Not tested: Firefox, Safari, real phones, and real assistive technology.
